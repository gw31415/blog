本文マークアップの採用一覧

Markdown出力では囲み記号の外側に必要な半角スペースを補います（例：日本語 **重要** です）。既存空白や行頭・行末には追加せず、本文JSON・入力時の発火条件は変更しません。再取り込みでは補った空白も本文になります。

意味、入力方法、4種類の出力、見た目を一つの表で比較するための実装スナップショット。

参照記事：かがん「strong, b, em, i, u, …、違いがわからんHTML要素の仕様を調べて『新しい見た目』を考えてみたら理解が深まった」。記事の16要素を含み、ブログの採用ノードも追加。意味の要約は検討用、記事の見た目案を採用したという意味ではありません。

保存できる文字書式を更新：strong・b・i・underline・em・mark・sub・supに対応（strike・code・linkも継続）。HTMLの意味とUI上の「太字」「斜体」等の呼び名を分けて検討できます。

Mod = macOSでは⌘、Windows/LinuxではCtrl。Spaceは半角空白。対話入力とMarkdown取り込みは別経路です。** / * / _ / __ / == は対話入力の割り当てです。正規Markdownの * / _ はem、** / __ はstrongの意味を維持します。表の出力列はこのリポジトリの変換結果を示し、各サービスでの表示保証ではありません。

入力・ショートカットの共通事項

  • Mod+/ でコマンドパレット。段落の先頭または空白の直後の / でも開きます。Mod+Enter は「ブロックから出る」操作のパレットを開き、標準の強制改行割り当てを上書きします。
  • 囲み記法（重要・太字・イタリック・下線・ハイライト・打ち消し）は、行頭・空白直後・非ASCII文字（漢字・かな・全角英数・句読点等）の直後で発火します。日本語文中では空白不要です。ASCIIの非空白文字直後では発火しません。Markdown全体の取り込みとは別の規則です。
  • 通常の貼り付けはプレーンテキストとして扱います。表記の取り込みはパレットのMarkdown取り込みを使用。HTMLは <br> と属性なしの対応インラインタグ（b・i・u・mark・sub・sup）だけを受け入れます。未採用要素は取り込めません。
  • 表のTab操作、リストのEnterなどは文脈で動作が変わります。キー欄は要素の作成・切替の主要な割り当てです。OS・ブラウザに予約されたキーとの衝突や実機の入力は今回未検証です。

出力を読むときの注意

  • /blog/ID.md は正規形式。?type=zenn、?type=github、?type=qiita が各出力。正規形式は本文のみ。Zennにはfront matter、GitHubには記事タイトルのH1を追加。副題は外部向けに通常段落として追加されます。
  • 独自ディレクティブは正規Markdownの拡張。外部向けの表題は表の前の段落、Mermaidキャプションはフェンス後の段落へ分離。ヘッダーなし表には空のヘッダーを追加します。元の本文JSONを保ち、構造変換は診断に記録します。リスト・引用等の入れ子でも同じ変換を適用します。
  • GitHub/Qiitaのインライン数式は $`x`$ で出力。同じ $x$ という文字列がコード・リンク先・通常文字にあっても数式へ置換しません。表セルの縦棒もエスケープします。
  • 正規Markdownは往復を目的としますが、外部向け出力は構造が変わることがあります。GitHub向けのdetailsはHTMLになり、現行インポーターではそのまま再取り込みできません。外部のスタイルはブログCSSを引き継ぎません。
