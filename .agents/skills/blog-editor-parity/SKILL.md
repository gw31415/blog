# blog-editor-parity

作業前に変更対象の閲覧・編集中・編集終了後を同じ内容とviewportで比較する。座標・寸法・改行位置を実DOM、computed style、必要なスクリーンショットで確認する。ソース文字列の一致だけで表示一致を判定しない。

- 既存の `tests/layout/article-layout-parity.spec.ts` と `package.json` の `test:layout` を利用する。変更箇所のケースを選び、無関係な全パターンの追加やTDDの強制をしない。
- コードブロックの言語表示／選択、表の行列操作など、編集UIの出現で本文を押し動かさない。見かけのずれは期待値だけを書き換えず、DOM・CSS・座標計算の原因を調べる。
- このサイトは角丸を追加せず、トグルの選択状態をhoverと区別する。ロード表示は既存の短い `…` に合わせる。新しいデザイン指定があればそちらを優先する。
- キーボード・下部ツールバーに関係する変更はiOS Safariのキーボード表示中のfocus、scroll、下端とsafe areaを観測する。SimulatorでタップがWeb側へ届いていない場合は、製品不具合や検証成功に置き換えず、未確認として扱う。
- 初期表示のSSRと編集時の遅延ロードを維持する。ロード境界を変更した場合は既存の `check:editor-chunk` を確認する。

PC・モバイルと閲覧／編集のうち、今回実際に確認した状態だけ報告する。普段の文言変更まで全画面検証へ広げない。
