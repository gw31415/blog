# blog-editor-parity

作業前に変更対象の閲覧・編集中・編集終了後を同じ内容とviewportで比較する。座標・寸法・改行位置を実DOM、computed style、必要なスクリーンショットで確認する。ソース文字列の一致だけで表示一致を判定しない。

- 既存の `tests/layout/article-layout-parity.spec.ts` を `pnpm exec playwright test` で利用する。変更箇所のケースを選び、無関係な全パターンの追加やTDDの強制をしない。
- コードブロックの言語表示／選択、表の行列操作など、編集UIの出現で本文を押し動かさない。見かけのずれは期待値だけを書き換えず、DOM・CSS・座標計算の原因を調べる。
- このサイトは角丸を追加せず、トグルの選択状態をhoverと区別する。ロード表示は既存の短い `…` に合わせる。新しいデザイン指定があればそちらを優先する。
- キーボード・下部ツールバーに関係する変更はiOS Safariのキーボード表示中のfocus、scroll、下端とsafe areaを観測する。SimulatorでタップがWeb側へ届いていない場合は、製品不具合や検証成功に置き換えず、未確認として扱う。
- 初期表示のSSRと編集時の遅延ロードを維持する。ロード境界を変更した場合は既存の `check:editor-chunk` を確認する。

PC・モバイルと閲覧／編集のうち、今回実際に確認した状態だけ報告する。普段の文言変更まで全画面検証へ広げない。

## 記事コンポーネントの見た目変更時の必須確認

Markdown記事のすべてのコンポーネント（段落・見出し・リスト・引用・表・コード・図・数式・補足・トグル、およびタイトル・副題・タグ・日付等）に適用する。CSS、DOM、フォント、空欄・placeholder、選択・focusの装飾、ツールバーの出現、画像・図の遅延描画を変更したら、機能の確認だけで完了にしない。編集開始／完了で余白・下線・枠の寸法を出し入れして本文やスクロール位置を動かすことは禁止する。

- padding、border幅、min-height、display、gap、タグのmarginは閲覧・編集・focusで同一にする。下線は透明な同幅borderを常時確保するか、レイアウトに参加しない装飾で描く。切替時は色やopacityだけを変える。scrollToの補正で寸法差を隠さない。
- 変更前後に同じ内容・viewportで、対象コンポーネントとその直後の要素、ヘッダー、本文先頭の矩形と実スクロール要素の位置を測る。空欄、複数タグ、折り返す長いタイトルも対象にする。
- PC・モバイル幅で記事上部とスクロール後の両方から、入力内容を変更せず「編集→完了」を最低2往復する。切替前後の座標・高さ・scroll位置が1 CSS px以内に保たれることを回帰テストで確認する。内部スクロールへの切替はwindow.scrollYだけで判定しない。
- テストがタイムアウトした場合は検証済みとしない。停止箇所を切り分け、未確認のモード・環境を明記する。iPhoneのキーボードや慣性スクロールはデスクトップのviewport変更では確認できない。

変更内容に応じ、画像・フォント・図の読込完了前後、エラー表示、トグルの開閉、選択・focus・hover、viewportや親文字サイズの変化も確認する。開閉や内容変更に伴う意図した寸法変化と、同一内容での閲覧／編集切替による意図しない移動を区別する。新しい再現条件を発見した際は、この対象範囲へ具体的な確認条件として追記する。無関係な全状態の総当たりは要求しない。
